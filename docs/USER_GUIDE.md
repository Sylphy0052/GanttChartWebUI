## 概要

**GanttChart WebUI** は、プロジェクトの課題（Issue）管理とガントチャート表示を行う現代的なWebアプリケーションです。階層構造を持つ課題管理、依存関係設定、リアルタイム通知機能を提供し、チーム全体でプロジェクトの進捗を効率的に追跡・管理できます。

### 主な機能

- **階層化Issue管理**: 親子関係を持つタスク構造
- **WBSツリー表示**: ドラッグ&ドロップによる階層編集
- **ガントチャート**: 視覚的なタイムライン表示
- **依存関係管理**: タスク間の順序制約設定
- **リアルタイム通知**: WebSocketによる即座の変更通知
- **コメント・添付ファイル**: マークダウン対応のコミュニケーション機能
- **プロジェクトレベル認証**: 共有パスワードによるアクセス制御

### 対応ブラウザ

- **推奨**: Chrome（最新版）、Firefox（最新版）、Safari（最新版）、Edge（最新版）
- **パフォーマンス目標**: 初期レンダリング <1.5秒、ドラッグレイテンシ <100ms

> **💡 ヒント**: 最適な動作のため、最新版のモダンブラウザの使用を強く推奨します。Internet Explorer はサポート対象外です。

## 始め方

### 1. アプリケーションにアクセス

Webブラウザでアプリケーションのトップページにアクセスしてください。

**アクセス方法:**
1. ブラウザのアドレスバーにサーバーのURL を入力
2. Enter キーを押してアクセス
3. トップページが表示されることを確認

### 2. プロジェクトの選択または作成

**初回アクセスの場合:**

![プロジェクト一覧画面](./images/project-list.png)
*プロジェクト一覧画面 - 既存プロジェクトの選択または新規作成が可能*

- **既存プロジェクト**: プロジェクト一覧からアクセスしたいプロジェクトを選択
- **新規プロジェクト**: 「新規プロジェクト作成」ボタンからプロジェクトを作成

### 3. 認証（必要に応じて）

プロジェクトにパスワードが設定されている場合、認証画面が表示されます：

![認証画面](./images/auth-screen.png)
*認証画面 - プロジェクトパスワードと権限レベルの選択*

**詳細手順:**
1. **プロジェクトパスワード**を入力
2. **権限レベル**を選択：
   - **Editor**: 編集可能（推奨）
   - **Viewer**: 閲覧のみ
3. **「認証」**ボタンをクリック
4. 認証成功後、プロジェクト画面にリダイレクト

### 4. 権限の確認

画面右上に表示される接続状態インジケーターで、現在の権限を確認できます：

- **🟢 Editor権限**: すべての機能が利用可能
- **🔵 Viewer権限**: 閲覧のみ可能
- **🔴 未認証**: 認証が必要

> **⚠️ 重要**: Viewer権限では編集操作（Issue作成・更新・削除、コメント投稿など）ができません。編集が必要な場合は、Editor権限で再認証してください。

## プロジェクト管理

### プロジェクト作成

#### 手順

![プロジェクト作成画面](./images/create-project.png)
*プロジェクト作成画面 - 基本情報の入力フォーム*

1. **ホーム画面**で「新規プロジェクト作成」をクリック
2. **プロジェクト情報**を入力：
   - **プロジェクト名**: 必須項目（例：「2025年度ECサイトリニューアル」）
   - **説明**: Markdown形式で詳細説明を記述
   - **共有パスワード**: アクセス制御用（任意、8文字以上推奨）
3. **「作成」**ボタンをクリック

#### プロジェクト設定のベストプラクティス

- **命名規約**: 「[年度]_[部署]_[プロジェクト名]」形式を推奨
- **説明の活用**: プロジェクトの目的、期間、主要成果物を記載
- **パスワード設定**: 機密性の高いプロジェクトには必ず設定

**説明欄の記述例:**
```markdown
# プロジェクト概要
ECサイトのユーザビリティ向上を目的としたシステムリニューアル

## 期間
2025年1月-6月

## 主要成果物
- 新デザインのWebサイト
- スマートフォン対応
- 決済システムの刷新

## 関係者
- PM: 田中太郎
- デザイナー: 佐藤花子
- エンジニア: 鈴木一郎
```

### プロジェクト設定の変更

#### 基本情報の編集

![プロジェクト設定画面](./images/project-settings.png)
*プロジェクト設定画面 - 基本情報の編集フォーム*

1. プロジェクト画面で**「設定」**タブを選択
2. 変更したい項目を編集
3. **「保存」**ボタンで変更を確定

> **📝 注意**: プロジェクト設定の変更には Editor 権限が必要です。

#### アクセス権限の管理

**Editor権限の特徴：**
- ✅ Issue・コメントの作成・編集・削除
- ✅ WBS構造の変更
- ✅ 依存関係の設定・変更
- ✅ ファイルのアップロード
- ✅ プロジェクト設定の変更

**Viewer権限の特徴：**
- ✅ すべての情報の閲覧
- ✅ ガントチャート・WBSツリーの表示
- ✅ データのエクスポート
- ❌ コメントの投稿（閲覧のみ）
- ❌ Issue の作成・編集・削除
- ❌ ファイルのアップロード

### プロジェクトのバックアップ・エクスポート

#### エクスポート手順

![エクスポート画面](./images/export-data.png)
*データエクスポート画面 - 形式選択とオプション設定*

1. プロジェクト画面で**「バックアップ」**メニューを選択
2. エクスポート形式を選択：
   - **JSON形式**: 完全なデータ構造（推奨）
   - **CSV形式**: 表計算ソフト用
3. エクスポートオプションを設定：
   - **添付画像を含める**: チェックするとファイルも含まれます
   - **削除されたデータを含める**: 論理削除されたデータの出力
4. **「エクスポート実行」**をクリック
5. ダウンロードされるファイルを保存

#### 注意事項

- エクスポートには添付画像も含まれます（最大10MB/ファイル）
- 大規模プロジェクトの場合、エクスポートに時間がかかる場合があります
- JSONファイルはシステム間でのデータ移行に使用可能です

## Issue管理

### Issueの基本概念

**Issue**は、プロジェクト内のタスク、課題、マイルストーンを表現する基本単位です。

#### Issue のタイプ

- **Task（タスク）**: 期間を持つ作業項目
- **Milestone（マイルストーン）**: 重要な節目（期間なし）

#### Issue のステータス

- **open**: 未着手（初期状態）
- **in_progress**: 作業中
- **done**: 完了
- **blocked**: 阻害要因により停止

### Issue の作成

#### 基本的な作成手順

![Issue作成画面](./images/create-issue.png)
*Issue作成画面 - 基本情報とスケジュールの入力フォーム*

**📋 Editor権限が必要な操作です。**

1. Issues画面で**「新規Issue作成」**ボタンをクリック
2. **基本情報**を入力：
   - **タイトル**: 作業内容を明確に表現（例：「ユーザー画面のデザイン作成」）
   - **説明**: Markdown形式で詳細を記述
   - **担当者**: メールアドレスまたは名前
   - **ステータス**: 初期状態を選択（通常は「open」）

3. **スケジュール情報**を設定：
   - **開始日**: タスク開始予定日（YYYY-MM-DD形式）
   - **終了日**: タスク完了予定日（開始日以降の日付）
   - **進捗率**: 0-100%（作成時は通常0%）
   - **工数**: 時間単位での見積もり（任意）

4. **分類・階層情報**を設定：
   - **親Issue**: 階層構造を作る場合に選択
   - **ラベル**: カテゴリ分類用のタグ（複数選択可）
   - **優先度**: 重要度の指標（Low/Medium/High）

5. **「作成」**ボタンで確定

#### 高度な作成オプション

**階層構造の作成：**
- 親Issueを選択することで、子タスクとして作成可能
- WBS番号（1.1.1形式）が自動生成されます
- 親子関係により、スケジュールの依存関係も自動設定

**ラベルの活用例：**
```
プロジェクト例: ECサイトリニューアル
- 「frontend」: フロントエンド開発関連
- 「backend」: バックエンド開発関連  
- 「design」: デザイン作業関連
- 「urgent」: 緊急対応が必要
- 「review」: レビューが必要
```

### Issue の編集・更新

#### 基本編集

![Issue編集画面](./images/edit-issue.png)
*Issue編集画面 - 既存データの更新フォーム*

**📋 Editor権限が必要な操作です。**

1. Issue一覧または詳細画面で**「編集」**ボタンをクリック
2. 変更したい項目を修正
3. **「保存」**ボタンで変更を確定

#### 楽観的排他制御

GanttChart WebUIは楽観的排他制御を実装しています：

- 他のユーザーが同時に編集している場合、警告が表示されます
- 最新の状態を確認してから再度編集してください
- バージョン競合が発生した場合、手動でマージする必要があります

![競合警告](./images/conflict-warning.png)
*競合警告ダイアログ - 同時編集時の警告表示*

#### 進捗の更新

**手動更新：**
1. Issue詳細画面で進捗率フィールドを編集
2. 数値入力（0-100）または スライダーで調整
3. 自動的に更新時刻が記録されます

**ガントチャートからの更新：**
1. ガントチャート上でプログレスバーをドラッグ
2. リアルタイムで進捗率が更新されます
3. 他のユーザーにも即座に通知されます

### Issue の削除

#### 論理削除の仕組み

GanttChart WebUIでは**論理削除**を採用しています：

- 削除されたIssueは非表示になりますが、データベースから完全に削除されません
- 変更履歴や依存関係の整合性が保たれます
- 必要に応じて復元が可能です

#### 削除手順

**📋 Editor権限が必要な操作です。**

1. Issue詳細画面で**「削除」**ボタンをクリック
2. 確認ダイアログで削除理由を入力（任意）
3. **「確認」**ボタンで削除を実行

**⚠️ 注意事項：**
- 子Issueが存在する場合、親Issueは削除できません
- 依存関係が設定されている場合、警告が表示されます
- 削除後も変更履歴には記録が残ります

## WBS機能

### WBS（Work Breakdown Structure）とは

WBSは、プロジェクトの作業を階層的に分解して管理する手法です。GanttChart WebUIでは、直感的なツリー表示とドラッグ&ドロップ操作でWBS構造を管理できます。

![WBSツリー表示](./images/wbs-tree.png)
*WBSツリー表示 - 階層構造の可視化と番号自動生成*

### WBSツリーの表示と操作

#### 基本的な表示

1. Issues画面で**「WBSツリー」**タブを選択
2. 階層構造がツリー形式で表示されます：
   - **WBS番号**: 1, 1.1, 1.1.1 形式で自動生成
   - **インデント**: 階層レベルに応じた視覚的な段差
   - **展開/折りたたみ**: 階層の表示/非表示切り替え

#### ツリー操作

**展開・折りたたみ：**
- 親Issueの左側にある**「▶」**または**「▼」**アイコンをクリック
- 子Issueの表示/非表示を切り替えられます
- 大規模プロジェクトでの表示最適化に有効

**Issue選択：**
- ツリーノードをクリックすると、そのIssueが選択状態になります
- ガントチャートとの連動表示が可能です
- 選択されたIssueは背景色でハイライト表示

### ドラッグ&ドロップによる構造変更

#### 階層変更の操作

![ドラッグ&ドロップ操作](./images/drag-drop-wbs.png)
*ドラッグ&ドロップ操作 - 直感的な階層構造の変更*

**📋 Editor権限が必要な操作です。**

1. **移動したいIssue**をマウスでドラッグ開始
2. **移動先の位置**にドロップ：
   - **他のIssueの上**: 兄弟関係として挿入
   - **他のIssueの右側**: 子Issueとして移動
   - **親Issueの左側**: 階層を上げて移動

3. **ドロップ先のハイライト**で位置を確認
4. マウスを離すと構造変更が実行されます

#### 操作結果の自動処理

**WBS番号の自動更新：**
- 構造変更と同時にWBS番号が再計算されます
- 例：1.1 → 2.3 への移動で番号体系が自動更新
- 変更は即座にデータベースに保存されます

**依存関係の検証：**
- 移動により循環依存が発生する場合、エラーが表示されます
- 依存関係の整合性が自動チェックされます
- 問題がある場合は移動をキャンセルします

### WBS番号システム

#### 自動生成ルール

- **レベル1**: 1, 2, 3, ...（トップレベルタスク）
- **レベル2**: 1.1, 1.2, 2.1, 2.2, ...（サブタスク）
- **レベル3**: 1.1.1, 1.1.2, 1.2.1, ...（詳細タスク）
- **最大推奨レベル**: 5レベルまで（深すぎる階層は管理が困難）

#### 並び順の管理

WBS番号は `sort_order` フィールドに基づいて決定されます：

1. **同一レベル内での並び順**はドラッグ&ドロップで変更可能
2. **親子関係の変更**により自動的に再計算
3. **削除されたIssue**の番号は欠番として扱われます

**例：番号体系の例**
```
1. システム設計
  1.1. データベース設計
    1.1.1. テーブル設計
    1.1.2. インデックス設計
  1.2. API設計
    1.2.1. エンドポイント設計
    1.2.2. スキーマ設計
2. フロントエンド開発
  2.1. 画面設計
  2.2. コンポーネント実装
```

## ガントチャート

### ガントチャートの基本操作

#### 表示モードの切り替え

Issues画面で**「ガント」**タブを選択すると、ガントチャート表示に切り替わります。

![ガントチャート基本表示](./images/gantt-basic.png)
*ガントチャート基本表示 - タスクバーと時間軸の表示*

**表示オプション：**
- **統合レイアウト**: WBSツリーとガントチャートを左右分割表示
- **ガント専用ページ**: ガントチャートに特化した全画面表示

#### タイムライン表示

**時間軸の表示：**
- **週表示**: デフォルトのビューモード（日-日曜日の週単位）
- **日表示**: 詳細な日程管理用（1日単位の表示）
- **月表示**: 長期プロジェクト用（月単位の表示）

**時間軸の操作：**
1. **ズームイン/アウト**: マウスホイールまたはズームボタン
2. **水平スクロール**: 左右の矢印ボタンまたはドラッグ
3. **期間指定**: 開始/終了日を直接入力して表示範囲を設定

### タスクバーの表示と機能

#### タスクバーの構成要素

![タスクバー詳細](./images/taskbar-details.png)
*タスクバー詳細表示 - 各要素の説明*

**通常のTask:**
- **タスクバー**: 期間に応じた横棒グラフ
- **プログレスバー**: 進捗率を示す色付きの内部バー
- **ラベル**: タスク名と担当者（右側に表示）
- **日程表示**: 開始日・終了日（ツールチップで表示）

**Milestone:**
- **ダイヤモンド型マーカー**: 特定日時のポイント表示
- **ラベル**: マイルストーン名
- **日付**: 設定された達成予定日

#### ステータス別の色分け

- **open（未着手）**: グレー系 (#6B7280)
- **in_progress（作業中）**: ブルー系 (#3B82F6)
- **done（完了）**: グリーン系 (#10B981)
- **blocked（阻害）**: レッド系 (#EF4444)

### ドラッグ&ドロップ編集

#### タスクバーの移動（Editor権限必要）

![ガントドラッグ操作](./images/gantt-drag-edit.png)
*ガントチャート編集操作 - ドラッグ&ドロップによる日程変更*

**水平移動（日程変更）：**
1. タスクバーの中央部分をドラッグ
2. 移動先の日付位置でドロップ
3. 開始日・終了日が自動調整されます
4. 依存関係がある場合、整合性がチェックされます

**サイズ変更（期間調整）：**
1. タスクバーの右端をドラッグ
2. 期間を延長または短縮
3. 終了日のみが変更されます（開始日は固定）

#### 進捗率の調整

**プログレスバーの操作：**
1. タスクバー内のプログレス部分をドラッグ
2. 進捗率がリアルタイムで更新
3. 0-100%の範囲で調整可能
4. 変更は自動保存されます

#### 操作時の制約

**編集制限：**
- 完了ステータス（done）のタスクは編集不可
- 阻害ステータス（blocked）のタスクは制限付き編集
- 依存関係による日程制約の自動チェック
- Viewer権限では一切の編集操作が不可

### 階層表示とWBS連動

#### WBSツリーとの同期

![統合レイアウト](./images/integrated-layout.png)
*統合レイアウト - WBSツリーとガントチャートの連動表示*

**選択の連動：**
- WBSツリーでIssueを選択 → ガントチャートで該当タスクがハイライト
- ガントチャートでタスクを選択 → WBSツリーで該当ノードがハイライト

**階層の視覚化：**
- 子タスクは親タスクの下に**インデント表示**
- **階層レベル**に応じて色の濃淡で区別
- **展開/折りたたみ**状態がWBSツリーと同期

#### 親子関係の視覚表現

- **親タスク**: 太い線で表示、子タスクの期間を包含
- **子タスク**: 細い線で表示、親タスクの内部に配置
- **サマリータスク**: 子タスクの最早開始〜最遅終了で自動計算

### ガントチャート専用レイアウト

#### 統合レイアウトページへのアクセス

1. Issues画面で**「ガント統合レイアウト」**ボタンをクリック
2. 左パネル：WBSツリー、右パネル：ガントチャートの分割表示
3. **分割バー**をドラッグして表示比率を調整可能（20%-80%）

## 依存関係管理

### 依存関係とは

依存関係は、タスク間の実行順序や制約を定義する機能です。GanttChart WebUIでは **Finish-to-Start（FS）**タイプの依存関係をサポートしています。

![依存関係の概要](./images/dependency-overview.png)
*依存関係の概要 - 先行タスク完了後に後続タスクが開始可能*

### 依存関係の基本概念

#### Finish-to-Start（FS）依存関係

- **先行タスク（Predecessor）**: 先に完了する必要があるタスク
- **後続タスク（Successor）**: 先行タスク完了後に開始可能なタスク
- **制約**: 先行タスクが完了するまで後続タスクは開始できません

#### 例：ソフトウェア開発プロジェクト

```
設計書作成 → コーディング → テスト → デプロイ
   (FS)        (FS)       (FS)
```

### 依存関係の作成

#### ガントチャート上での作成（Editor権限必要）

![依存関係作成](./images/create-dependency.png)
*依存関係作成 - ガントチャート上でのドラッグ&ドロップ操作*

**ドラッグ&ドロップ方式：**
1. **先行タスク**のタスクバー右端にマウスを合わせる
2. **接続ポイント**（小さな円）が表示される
3. 接続ポイントから**後続タスク**へドラッグ
4. **依存関係線**が表示されたらドロップ
5. 確認ダイアログで依存関係を確定

#### 依存関係エディターでの作成

1. ガントチャート右上の**「依存関係編集」**ボタンをクリック
2. **依存関係エディター**が開く
3. **先行タスク**と**後続タスク**をプルダウンから選択
4. **「追加」**ボタンで依存関係を作成

### 依存関係の表示

#### ガントチャート上の視覚表現

![依存関係表示](./images/dependency-visualization.png)
*依存関係の視覚表現 - 矢印線による依存関係の表示*

**矢印線の表示：**
- **先行タスク**の終了点から**後続タスク**の開始点への矢印
- **色分け**: 正常（青）、制約違反（赤）、選択中（緑）
- **ラベル**: 依存関係タイプ（FS）の表示

#### 制約違反の警告

**日程矛盾の検出：**
- 後続タスクが先行タスクより早く開始する場合
- **赤色の矢印線**で警告表示
- **警告アイコン**とエラーメッセージ

### スケジュール自動調整

#### 依存関係に基づく日程計算

**自動調整のトリガー：**
- 先行タスクの終了日変更
- 依存関係の新規作成
- タスクの削除や移動

**調整アルゴリズム：**
1. **先行タスクの終了日**を基準に計算
2. **後続タスクの開始日**を自動調整
3. **連鎖的な調整**で全体の整合性を保持
4. **制約違反の回避**

#### 調整結果の通知

**リアルタイム通知：**
- スケジュール調整完了時に画面上部に通知
- **調整されたタスク一覧**の表示
- **WebSocket**による即座の反映

### 依存関係の削除

#### 削除方法

**ガントチャート上での削除：**
1. **依存関係線**を右クリック
2. コンテキストメニューから**「削除」**を選択
3. 確認ダイアログで削除を確定

**依存関係エディターでの削除：**
1. **依存関係一覧**で削除対象を選択
2. **「削除」**ボタンをクリック
3. 確認ダイアログで削除を確定

#### 削除の影響

- **制約の解除**: 後続タスクの日程制約が解除されます
- **スケジュール再計算**: 必要に応じて全体スケジュールが調整されます

### 循環依存の防止

#### 循環依存とは

A → B → C → A のような、タスク間の無限ループを形成する依存関係です。

#### 自動検出システム

**作成時チェック：**
- 依存関係作成時に循環依存を自動検出
- **エラーメッセージ**で作成を阻止
- **代替案の提示**

**例：**
```
❌ 無効な依存関係
タスクA → タスクB → タスクA

✅ 正しい依存関係
タスクA → タスクB → タスクC
```

### 依存関係の分析機能

#### 統計情報の表示

ガントチャート画面下部に表示される情報：

- **総依存関係数**: プロジェクト内の全依存関係件数
- **タイプ別内訳**: FS依存関係の数
- **制約違反数**: 日程矛盾のある依存関係数

#### クリティカルパス分析

**クリティカルパスとは：**
プロジェクト完了に最も時間がかかる一連のタスク経路

**表示機能：**
- クリティカルパス上のタスクを**太線**で強調表示
- **遅延リスク**の可視化
- **最短完了日**の計算表示

### 競合処理とバージョン管理

#### 楽観的排他制御

**同時編集の検出：**
1. 複数ユーザーが同じIssueを編集開始
2. **編集中表示**で他ユーザーに通知
3. 先に保存したユーザーの変更が優先
4. 後続ユーザーには**競合警告**を表示

#### 競合解決の手順

**競合発生時の対応：**
1. **競合警告ダイアログ**の表示
2. **現在の最新状態**の確認
3. **自分の変更内容**との比較
4. **手動マージ**または**再編集**の選択

**例：競合シナリオ**
```
ユーザーA: タイトルを「設計」→「詳細設計」に変更
ユーザーB: 同時に進捗率を50%→75%に変更

結果: 
- 先に保存されたユーザーAの変更が確定
- ユーザーBには最新状態を表示して再編集を促す
```

- **高（High）**: Issue作成・削除、スケジュール大幅変更

- **低（Low）**: 進捗率変更、小規模な編集

#### ブラウザ通知

**Webブラウザの通知機能：**
- 初回アクセス時に通知許可を要求
- **重要な変更**のみブラウザ通知
- **サウンド**の ON/OFF 設定可能

## よくある質問（FAQ）

### 基本操作について

#### Q: Issueを作成したが、ガントチャートに表示されません

**A:** 以下を確認してください：

1. **開始日・終了日の設定**: 両方が設定されているか確認
2. **ステータス**: ブロック状態（blocked）になっていないか確認  
3. **表示フィルター**: 現在のフィルター設定で該当Issueが除外されていないか確認
4. **ブラウザキャッシュ**: Ctrl+F5でページを強制再読み込み

#### Q: WBSツリーでドラッグ&ドロップができません

**A:** 権限を確認してください：

1. **Editor権限**: Viewer権限ではWBS構造の変更はできません
2. **認証状態**: プロジェクトパスワード認証が有効か確認
3. **ブラウザ対応**: モダンブラウザ（Chrome、Firefox、Safari、Edge の最新版）を使用
4. **JavaScript有効**: ブラウザでJavaScriptが有効になっているか確認

#### Q: 依存関係の矢印線が表示されません

**A:** 以下を順番に確認してください：

1. **タスクの日程**: 先行・後続タスクの両方に日程が設定されているか
2. **表示領域**: ガントチャートの表示期間内にタスクが含まれているか
3. **画面サイズ**: ブラウザのズームレベルが適切か（100%推奨）
4. **依存関係データ**: 依存関係が正しく作成されているか一覧で確認

#### Q: 権限レベルを変更したい

**A:** 認証を再実行してください：

1. **ログアウト**: 画面右上の権限表示部分をクリック
2. **再認証**: プロジェクトパスワードを再入力
3. **権限選択**: Editor または Viewer を選択
4. **適用確認**: 画面右上のインジケーターで権限を確認

### エラー・トラブル

#### Q: 「バージョン競合が発生しました」エラーが表示されます

**A:** 楽観的排他制御によるエラーです：

1. **最新データの確認**: ページを再読み込みして最新状態を確認
2. **再編集**: 最新データを基に変更内容を再入力
3. **通知確認**: 他のユーザーが同時編集していないか確認
4. **保存タイミング**: こまめに保存して競合リスクを軽減

**対処手順の詳細:**
```
1. エラーダイアログの「最新データを取得」をクリック
2. 他ユーザーの変更内容を確認
3. 自分の変更内容を再入力
4. 保存前に他ユーザーの作業状況を確認
```

#### Q: WebSocket接続が切断される（赤いインジケーター）

**A:** ネットワーク環境を確認してください：

1. **ネットワーク安定性**: インターネット接続が安定しているか
2. **プロキシ・ファイアウォール**: WebSocket通信がブロックされていないか
3. **ブラウザの設定**: WebSocketが有効になっているか
4. **自動再接続**: 通常は数秒後に自動復旧します

**技術者向け確認項目:**
- WebSocket ポート（通常 80/443）の開放確認
- プロキシサーバーでの WebSocket サポート確認
- SSL証明書の有効性確認

#### Q: アップロードした画像が表示されません

**A:** ファイル形式とサイズを確認してください：

**対応形式:** JPEG、PNG、GIF、WebP のみ
**最大サイズ:** 10MB
**解決方法:**
1. ファイル形式を変換（例：BMP → PNG）
2. 画像サイズを圧縮（オンライン圧縮ツール等を使用）
3. ブラウザキャッシュをクリア
4. 別の画像での動作確認

#### Q: 「権限がありません」エラーが表示されます

**A:** 以下を確認してください：

1. **現在の権限**: 画面右上のインジケーターで権限を確認
2. **必要な権限**: 実行したい操作に必要な権限レベルを確認
3. **再認証**: Editor権限で認証を再実行
4. **プロジェクト設定**: プロジェクト管理者にアクセス権限を確認

### 機能・仕様について

#### Q: マイルストーンとタスクの違いは何ですか？

**A:** 以下の違いがあります：

**タスク（Task）:**
- ✅ 期間を持つ作業項目
- ✅ 開始日〜終了日の期間設定
- ✅ 進捗率の管理可能
- ✅ ガントチャートでは横棒で表示

**マイルストーン（Milestone）:**
- ✅ 特定日時の重要な節目
- ✅ 開始日=終了日（期間なし）
- ❌ 進捗率は管理しない
- ✅ ガントチャートではダイヤモンド型で表示

#### Q: WBS番号を手動で変更できますか？

**A:** WBS番号は自動生成のため、手動変更はできません：

**自動生成の利点:**
- 階層変更時の自動更新
- 番号体系の一貫性保証
- 重複番号の回避

**番号を変更したい場合:**
1. ドラッグ&ドロップでIssueの位置を変更
2. 自動的に適切なWBS番号が再生成されます

#### Q: 複数のプロジェクトを同時に管理できますか？

**A:** 可能です：

**マルチプロジェクト機能:**
- ✅ プロジェクト一覧からの切り替え
- ✅ ブラウザタブでの並行表示
- ✅ プロジェクトごとの独立した認証
- ✅ データの完全分離

**推奨する使い方:**
- 関連プロジェクトの並行管理
- 異なる部署のプロジェクト分離
- 本番・テスト環境の使い分け

#### Q: Issue の階層に制限はありますか？

**A:** 以下の制限があります：

**推奨階層深度:**
- **理想**: 3-4レベル（1.1.1.1まで）
- **上限**: 5レベル（システム制限）
- **パフォーマンス**: 深い階層は表示速度に影響

**階層設計のベストプラクティス:**
1. **レベル1**: 主要なフェーズ・工程
2. **レベル2**: サブフェーズ・大項目
3. **レベル3**: 具体的なタスク
4. **レベル4**: 詳細作業（必要に応じて）

### パフォーマンス

#### Q: 大量のIssueがあるとき、動作が重くなります

**A:** 以下の最適化を試してください：

**推奨Issue数:**
- **理想**: 50Issue以下/プロジェクト
- **上限**: 200Issue/プロジェクト
- **限界**: 500Issue（動作保証外）

**パフォーマンス改善方法:**
1. **フィルター活用**: ステータス・担当者でフィルタリング
2. **階層折りたたみ**: 使用しない階層は折りたたみ
3. **ブラウザ最適化**: 他のタブを閉じる、メモリ使用量を確認
4. **定期的なデータ整理**: 完了したIssueのアーカイブ

**システム管理者向け対策:**
- データベースインデックスの最適化
- サーバーリソースの増強
- キャッシュ戦略の見直し

#### Q: モバイルデバイスでも使用できますか？

**A:** 制限付きで使用可能です：

**対応状況:**
- **💻 デスクトップPC**: フル機能対応（推奨）
- **📱 タブレット**: iPad、Android タブレット（実用的）
- **📱 スマートフォン**: 閲覧のみ推奨

**デバイス別制限事項:**
```
タブレット（iPad/Android）:
✅ 閲覧・確認作業
✅ 基本的な編集
⚠️ ドラッグ&ドロップ操作が困難
⚠️ ガントチャートの表示領域が狭い

スマートフォン:
✅ 閲覧・確認のみ
❌ 編集作業は困難
❌ 複雑な操作は不可
```

**推奨環境:**
- **画面サイズ**: 13インチ以上
- **解像度**: 1280x720 以上
- **操作デバイス**: マウス付きPC

### データ管理・バックアップ

#### Q: データのバックアップはどうすればよいですか？

**A:** 以下の方法でバックアップできます：

**手動バックアップ:**

#### Q: プロジェクトデータを他のシステムに移行できますか？

**エクスポートデータの内容:**

**他システムへの移行:**

#### Q: 削除したデータを復旧できますか？

**復旧可能な範囲:**

- ⚠️ 削除された添付ファイル（条件付き）

**復旧手順:**
1. システム管理者へ復旧依頼

3. データベースからの復旧作業
4. 整合性チェックと動作確認

   - ログアウト → 再ログイン

3. セッションの再確立
   - ブラウザの再起動
   - キャッシュ・Cookieクリア

4. ブラウザの再起動
   - 完全にブラウザを終了
   - タスクマネージャーでプロセス確認
```

**ネットワークエラー:**
```
確認項目:
1. ネットワーク接続の安定性
   - ping コマンドでサーバー疎通確認
   - 他のWebサイトへのアクセス確認

```

   - チーム内での作業分担確認
   - 同時編集の回避策検討
```

**日程データ不備:**

- **日付形式**の確認（YYYY-MM-DD）
- **論理的な日程**の確認（開始≤終了）

**確認手順:**
```
1. Issue一覧画面で日程データ確認
2. 不正な日付（未来すぎる、過去すぎる）の修正
3. 開始日 > 終了日 になっているデータの修正
4. 日付が未設定のIssueの確認
```

**表示範囲外:**
- **タイムライン期間**の調整
- **ズームレベル**の調整
- **スクロール位置**の確認

**調整方法:**
```
1. ガントチャート上部の期間選択で表示範囲を変更
2. ズームボタン（+/-）で表示スケール調整
3. 左右スクロールで目的の期間を表示
4. 「今日」ボタンで現在日付にフォーカス
```

**ブラウザレンダリング:**
- **画面解像度**の確認
- **ブラウザズーム**の調整（100%推奨）
- **グラフィック描画**の最適化

1. **階層構造の活用**: WBSツリーで作業を適切に分解
2. **依存関係の設定**: タスク間の制約を明確化
3. **リアルタイム協調**: 複数メンバーでの同時作業
4. **進捗の可視化**: ガントチャートでの状況把握
5. **コミュニケーション**: コメント機能での情報共有

### 権限レベル別推奨用途

**Viewer権限の活用場面:**
- 👥 ステークホルダーへの進捗報告
- 📊 プロジェクト状況の確認・監視
- 📈 データ分析・エクスポート作業
- 🔍 課題・リスクの発見・報告

**Editor権限の活用場面:**
- ✏️ プロジェクト計画の策定・更新
- 🔄 タスクの作成・編集・進捗更新
- 💬 チーム内コミュニケーション
- 🔗 依存関係の設定・調整

### システム運用のベストプラクティス

**データ管理:**
- 定期的なバックアップ（週次推奨）
- 完了プロジェクトの適切なアーカイブ
- 不要データの定期的な整理

**パフォーマンス維持:**
- プロジェクト規模の適切な管理（50-200 Issue）
- 階層深度の制限（5レベル以内）
- 定期的なシステムメンテナンス

**セキュリティ:**
- 適切な権限レベルの設定
- プロジェクトパスワードの定期更新
- 機密プロジェクトの適切な管理
